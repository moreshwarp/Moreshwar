Studying

Reliability of AI infrastructure

When a training job or an inference server fails halfway through, how fast can it recover, and what work is lost?

Large AI jobs run for days on thousands of chips. One failed machine can stop all of them. I am studying checkpointing, failure detection and recovery, and how serving systems handle many multi-step AI-agent requests at once.

Fieldnotes

Queues and tail latency

Why does the slowest 1% of requests decide how fast a whole system feels?

A page that calls 100 services must wait for the slowest one. Small delays in queues add up, so a system that is fast on average can still feel slow.

Tail latencyQueues

Fieldnote

Consistency in distributed systems

When copies of the same data disagree, what exactly does a user see?

Systems keep many copies of data so they can survive failures. The copies cannot always agree at the same moment. Ordering, clocks and consensus decide what “correct” means.

Experiment

Performance diagnosis across the stack

When software is slow, is the cause the code, the operating system, memory, or the network?

Each layer hides the layers below it. I build small telemetry tools that measure what one layer can see, and that state clearly what it cannot see.

Telemetry LabMachine Check

Studying

Operating systems and concurrency

How much control should an operating system give to applications, and what breaks when many threads share memory?

I am reading the classic answers, from Exokernel to modern kernels, and working through low-level C++ concurrency to see the problems at first hand.

Studying

Energy-aware computing

How much useful work can a system do per unit of energy, and how do we measure it honestly?

Data centres for AI use a lot of power. Scheduling work on GPUs and CPUs with energy in mind is a systems problem as much as a hardware problem.

About

I am Moreshwar, a systems software researcher. My interests are systems software, distributed systems, operating systems, AI infrastructure, reliability, energy-aware computing and performance diagnosis.

Before research, I spent about seven years building web front ends for products used in many countries. That work taught me how real users meet a system: through the slowest request, the confusing error and the page that does not load. Now I study the layers underneath.

I write for curious readers, not only for specialists. If a note here is wrong or unclear, please tell me. Corrections make the work better.
